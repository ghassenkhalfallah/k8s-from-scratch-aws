Each box is an Ansible building block. Click one to see what it does, how it fits, and a real example from your project.

1

Parse playbook

Ansible reads site.yml, validates YAML syntax, and builds an ordered list of plays. Each play declares which hosts to target and which roles to apply.

2

Load inventory + config

Reads ansible.cfg for settings (SSH pipelining, fact caching, forks). Parses hosts.ini to build the host list with connection params, groups, and group_vars.

3

Gather facts (smart)

For each target host, Ansible checks the fact cache. If fresh (fact_caching_timeout), reuses cached facts. Otherwise, SSHs in and runs the setup module to collect OS, IP, CPU, memory info.

4

Merge variables

Ansible merges variables from all sources (22 levels). From lowest to highest: role defaults → inventory vars → group_vars → host_vars → play vars → role vars → task vars → extra vars (-e). Higher wins.

5

Execute roles → tasks

Each role's tasks/main.yml runs in order. Every task calls exactly one module. Jinja2 templates are rendered with merged variables. when: conditions are evaluated to skip tasks.

6

Module execution on remote

Ansible generates a Python script from the module + args, transfers it via SSH (through bastion ProxyCommand), executes it on the remote host, and collects the JSON result: ok, changed, or failed.

7

Register + conditionals

Task results are captured with register:. Later tasks use when: result.rc != 0 to branch. This is how your master role checks if kubeadm already ran — stat on admin.conf, skip init if it exists.

8

Handlers fire at end of play

Tasks that changed state can notify: a handler. Handlers are deferred — they run once at the end of the play, even if notified multiple times. Example: restart containerd runs once after all config changes.

9

Next play or finish

After all tasks + handlers complete for a play, Ansible moves to the next play (common → master → workers → ingress). When all 4 plays finish, the recap shows ok/changed/failed per host.

Higher = wins when the same variable is defined at multiple levels. Hover to highlight.

Your project uses 3 levels: Role defaults (ingress ports), group_vars/all.yml (k8s version, CIDRs), and inventory vars (pod_cidr, service_cidr from Terraform). This keeps things simple — no conflicts.
